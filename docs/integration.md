# Core and SDK integration

Install an exact independently verified release and construct neutral declarations directly. Wrap every portal
workspace, navigation, route or template declaration in PortalContributionAdmission with a canonical owner and
required capability. Explicit exposure is required; false is the default. Core must independently check trust,
lifecycle and current capability before activation, rendering or dispatch.

The [Core contract](core-contract.md) specifies same-owner reference checks, preservation of route/navigation
capabilities, byte/UTF-8 bounds and executable host responsibilities. No ConfigProvider, renderer, dispatcher,
authentication flow or active registry is supplied. Core and SDK retain HTTP-oriented bindings and actual services.

Use [source-map.json](source-map.json) and the [release record](release-record.md) to reconcile current consumer
imports, configuration, reflection and fixtures with the selected package. Remove duplicate production declarations
and their portable implementation tests together only after verified replacement. Keep Core service, database,
trust/lifecycle, delivery, browser, recovery and composition tests. No aliases or dual PSR-4 roots are supported.

Preserve caller transaction and optimistic-concurrency boundaries when declarations lead to persistence or delivery.
The package validates declaration consistency and never grants authority itself.
